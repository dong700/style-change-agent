# 超大文件风格迁移系统 - 完整使用指南

## 一、系统概述

本系统支持处理超大 PDF/Word 文档（如 250MB+），实现：
- OCR 文字识别（扫描版 PDF）
- 文档智能切分
- 风格特征提取
- 风格迁移改写

---

## 二、处理流程

```
┌─────────────────────────────────────────────────────────────────┐
│                      超大文件处理流程                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 文件上传                                                     │
│     └─> 支持格式: PDF, DOCX, TXT                                 │
│     └─> 最大支持: 500MB                                          │
│                                                                 │
│  2. OCR 识别（扫描版 PDF）                                       │
│     └─> 使用 PaddleOCR 本地识别                                  │
│     └─> 结果缓存到 cache/ocr/ 目录                               │
│     └─> 再次上传同一文件直接使用缓存                              │
│                                                                 │
│  3. 文档切分                                                     │
│     └─> 按章节/段落智能切分                                      │
│     └─> 每个片段约 500 字符                                      │
│                                                                 │
│  4. 风格分析                                                     │
│     └─> 调用 LLM 分析每个片段的风格                              │
│     └─> 结果缓存到 outputs/style_cache/ 目录                     │
│     └─> 支持自动切换模型                                         │
│                                                                 │
│  5. 建立索引                                                     │
│     └─> 使用 FAISS 建立向量索引                                  │
│     └─> 支持相似片段检索                                         │
│                                                                 │
│  6. 风格改写（可选）                                             │
│     └─> 根据目标风格改写片段                                     │
│     └─> 保持原文核心信息                                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 三、模型配置

### 支持的模型类型

| 类型 | 模型 | 速度 | 成本 | 说明 |
|------|------|------|------|------|
| **DeepSeek API** | deepseek-chat | ★★★★★ | 0.001元/千token | 推荐，性价比最高 |
| **DeepSeek API** | deepseek-reasoner | ★★★★☆ | 0.002元/千token | 推理模型 |
| **Ollama 本地** | deepseek-r1:7b | ★★★★★ | 免费 | 本地最快 |
| **Ollama 本地** | qwen3.5:2b | ★★★★☆ | 免费 | 本地备选 |
| **Ollama 本地** | qwen3.5:4b | ★★★☆☆ | 免费 | 本地备选 |
| **阿里云百练** | qwen3.6-flash | ★★★★★ | 免费额度 | 云端备选 |

### 推荐配置

1. **有 DeepSeek API Key**：使用 `deepseek-api:deepseek-chat`
2. **无 API Key，有本地 GPU**：使用 `ollama:deepseek-r1:7b`
3. **无本地 GPU**：使用 `qwen3.6-flash`（阿里云百练）

## 四、环境配置

### 4.1 安装依赖

```bash
# 创建 conda 环境
conda create -n style_ocr python=3.10
conda activate style_ocr

# 安装基础依赖
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 安装 OCR 依赖（如需处理扫描版 PDF）
pip install -r requirements_ocr.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 4.2 配置 API Key

**方式一：环境变量（推荐）**
```bash
# DeepSeek API
set DEEPSEEK_API_KEY=your_deepseek_api_key

# 阿里云百练
set DASHSCOPE_API_KEY=your_dashscope_api_key
```

**方式二：修改配置文件**
编辑 `web_app/model_config.json`：
```json
{
  "deepseek_api_key": "your_deepseek_api_key"
}
```

### 4.3 安装 Ollama（可选）

如需使用本地模型：
```bash
# 下载安装 Ollama
# https://ollama.ai/download

# 拉取模型
ollama pull deepseek-r1:7b
ollama pull qwen3.5:2b

# 启动服务
ollama serve
```

## 六、使用步骤

### 6.1 上传源文件

1. 访问 http://localhost:5000/large_text/
2. 选择模型（推荐 DeepSeek API）
3. 上传 PDF/DOCX 文件
4. 等待 OCR 和风格分析完成

- 片段列表

1. 输入需要改写的文本
2. 系统自动匹配相似片段的风格
3. 按目标风格改写

## 七、缓存机制

### 7.1 OCR 缓存

- 位置：`cache/ocr/`
- 命名：`{文件hash}_{ocr引擎}_ocr.json`
- 效果：同一文件再次上传直接使用缓存

### 7.2 风格分析缓存

- 位置：`outputs/style_cache/`
- 命名：`{文本hash}_{模型名}.json`
- 效果：相同文本片段直接使用缓存

## 九、常见问题

### Q1: OCR 识别失败？
- 检查 PaddleOCR 是否正确安装
- 检查 Poppler 是否安装（PDF 转图片需要）

### Q2: 模型调用失败？
- DeepSeek API：检查 API Key 是否正确
- Ollama：检查服务是否启动（`ollama serve`）
- 系统会自动切换到备用模型

### Q3: 处理速度慢？
- 使用 DeepSeek API（云端）最快
- 本地模型建议使用 deepseek-r1:7b

### Q4: 内存不足？
- 减小 `analysis_max_length` 参数
- 分批处理大文件
