# 超大文本处理模块 - 完整使用说明

## 功能概述

超大文本处理模块是一个完整的 Agent 工作流系统，支持：

- ✅ **PDF 和 Word 文档上传**
- ✅ **智能文档切分**（按章节、段落、句子）
- ✅ **批量风格提取**（多维度风格分析）
- ✅ **智能索引构建**（语义检索 + 主题检索）
- ✅ **智能改写**（风格迁移）
- ✅ **质量检查**（事实一致性检查）
- ✅ **进度保存和加载**
- ✅ **结果导出**

## 访问方式

启动应用后，访问：

```
http://localhost:5000/large_text
```

## 完整工作流程

### 第一步：处理源文档（提取风格）

1. **上传源文档**
   - 点击"源文档处理"标签页
   - 上传 PDF 或 Word 文档（如校史）
   - 点击"开始处理"

2. **自动处理流程**
   ```
   文档切分 → 风格提取 → 建立索引 → 保存结果
   ```

3. **查看结果**
   - 总片段数
   - 章节数
   - 平均片段长度

4. **保存分析结果**
   - 点击"保存分析结果"
   - 输入名称
   - 下次可以直接加载

### 第二步：改写目标文档

1. **上传目标文档**
   - 点击"目标文档改写"标签页
   - 上传 PDF 或 Word 文档

2. **选择源风格**
   - 如果刚处理过源文档，会自动使用
   - 或从"已保存的分析"中加载

3. **开始改写**
   - 点击"开始改写"
   - 系统会：
     - 切分目标文档
     - 智能匹配风格
     - 分批改写
     - 质量检查

4. **查看结果**
   - 高质量片段数量
   - 需审核片段数量
   - 低质量片段数量

### 第三步：查看详细结果

1. **切换到"结果查看"标签页**
2. **查看每个片段的对比**
   - 原文
   - 改写后
   - 质量等级
3. **导出结果**
   - JSON 格式
   - Word 审核文档

### 第四步：管理已保存的分析

1. **切换到"已保存的分析"标签页**
2. **查看所有保存的分析**
3. **点击"加载"使用之前的分析结果**

## 核心功能详解

### 1. 文档切分策略

**切分粒度**：
- **第一层**：按章节切分（一级标题）
- **第二层**：按段落切分（200-400字片段）
- **第三层**：保存完整句子（避免断句）

**支持的格式**：
- ✅ Word (.docx)
- ✅ PDF (.pdf)

**标题识别**：
- Word 样式（Heading 1-6）
- 中文编号（第一章、第一节）
- 数字编号（1.、2.、3.）

### 2. 风格提取维度

**可量化特征**：
- 句法特征（平均句长、句长标准差、标点密度）
- 词汇特征（词汇丰富度、高频词占比）
- 可读性特征（Flesch-Kincaid 等级）

**LLM 分析特征**：
- 词汇风格（口语化/书面化、华丽/朴实）
- 句法风格（长句/短句、并列/复合句）
- 修辞风格（比喻、拟人、排比）
- 语气与情感（幽默、严肃、讽刺）
- 语体与正式度（公文、学术、新闻）
- 时代感与文化风格（古风、现代、地域特色）
- 叙事风格（第一人称、第三人称）

**主题标签**：
- 自动提取关键词
- 用于主题匹配

### 3. 智能检索匹配

**三级匹配策略**：

```
1. 语义相似度 > 0.75
   ↓ 使用最相似片段的风格
   
2. 主题标签匹配
   ↓ 使用主题相关片段的风格
   
3. 全局风格（兜底）
   ↓ 使用整体平均风格
```

**索引结构**：
- **语义索引**：基于特征向量（FAISS）
- **主题索引**：基于关键词（倒排索引）
- **章节索引**：按章节组织

### 4. 改写质量检查

**检查维度**：
- ✅ 事实一致性（时间、人物、事件、数据）
- ✅ 风格相似度
- ✅ 长度相当性

**质量等级**：
- **高质量**：事实一致 + 风格相似度高
- **需审核**：事实轻微偏差或风格相似度中等
- **低质量**：事实不一致或风格相似度低

**审核文档**：
- 自动生成 Word 文档
- 包含原文、改写、问题描述
- 方便人工审核和修改

## API 接口说明

### 1. 处理源文档

```http
POST /large_text/api/large_text/process_source
Content-Type: multipart/form-data

参数：
- file: 文档文件（.docx 或 .pdf）

返回：
{
  "success": true,
  "analysis_id": "uuid"
}
```

### 2. 处理目标文档

```http
POST /large_text/api/large_text/process_target
Content-Type: multipart/form-data

参数：
- file: 文档文件
- source_analysis_id: 源分析 ID

返回：
{
  "success": true,
  "task_id": "uuid"
}
```

### 3. 查询进度

```http
GET /large_text/api/large_text/progress/<type>/<task_id>

返回：
{
  "status": "processing|completed|failed",
  "progress": 50,
  "message": "正在处理...",
  "results": {...}
}
```

### 4. 保存分析

```http
POST /large_text/api/large_text/save_analysis
Content-Type: application/json

参数：
{
  "analysis_id": "uuid",
  "name": "分析名称"
}
```

### 5. 获取已保存的分析

```http
GET /large_text/api/large_text/saved_analyses

返回：
{
  "analyses": [
    {
      "id": "uuid",
      "name": "分析名称",
      "created_at": "2024-01-01",
      "total_fragments": 100,
      "total_chapters": 10
    }
  ]
}
```

## 配置说明

### 模型配置

系统使用通义千问模型，可以在代码中修改：

```python
# 批量风格提取
extractor = BatchStyleExtractor(model='qwen-plus')

# 改写 Agent
rewriter = RewriteAgent(model='qwen-plus')

# 质量检查
checker = QualityChecker(model='qwen-plus')
```

**推荐配置**：
- **qwen-turbo**：快速测试，成本低
- **qwen-plus**：平衡推荐 ⭐
- **qwen-max**：效果最好，成本高

### 切分参数

```python
processor = DocumentProcessor(
    min_fragment_length=200,  # 最小片段长度
    max_fragment_length=400   # 最大片段长度
)
```

### 批处理大小

```python
# 风格提取
results = extractor.extract_batch(
    fragments,
    batch_size=5  # 每批处理 5 个片段
)

# 改写
results = rewriter.rewrite_batch(
    fragments,
    style_index,
    batch_size=5  # 每批处理 5 个片段
)
```

## 性能优化

### 1. 使用 FAISS 加速检索

```bash
pip install faiss-cpu
```

FAISS 可以显著提高大规模片段的检索速度。

### 2. 调整批处理大小

- **小批次（3-5）**：更稳定，适合测试
- **中批次（5-10）**：平衡推荐 ⭐
- **大批次（10+）**：更快，但可能不稳定

### 3. 使用更快的模型

- **qwen-turbo**：速度最快（2-4秒/片段）
- **qwen-plus**：速度适中（5-8秒/片段）
- **qwen-max**：速度较慢（10-15秒/片段）

### 4. 保存进度

系统会自动保存处理进度，即使中断也可以恢复：

```python
# 风格提取
results = extractor.extract_batch(
    fragments,
    save_progress=True,
    progress_file='progress.json'
)

# 改写
results = rewriter.rewrite_batch(
    fragments,
    style_index,
    save_progress=True,
    progress_file='rewrite_progress.json'
)
```

## 常见问题

### Q1: PDF 文档处理失败

**原因**：PyPDF2 未安装或 PDF 格式特殊

**解决**：
```bash
pip install PyPDF2
```

如果仍然失败，尝试：
1. 将 PDF 转换为 Word 格式
2. 使用其他 PDF 提取工具

### Q2: 处理速度太慢

**原因**：使用 qwen-max 模型或批处理大小太小

**解决**：
1. 切换到 qwen-plus 或 qwen-turbo
2. 增加批处理大小（如 10）
3. 使用 FAISS 加速检索

### Q3: 内存不足

**原因**：文档太大或片段太多

**解决**：
1. 减小批处理大小
2. 增加片段长度（如 500-800 字）
3. 分批处理文档

### Q4: 改写质量不好

**原因**：源文档风格提取不充分或匹配不准确

**解决**：
1. 确保源文档足够长（建议 5000+ 字）
2. 检查风格标签是否准确
3. 手动调整风格标签
4. 使用 qwen-max 模型

### Q5: 事实不一致

**原因**：LLM 改写时引入了虚构内容

**解决**：
1. 查看审核文档
2. 人工修改不一致的部分
3. 调整改写提示词
4. 使用更严格的约束

## 使用建议

### 最佳实践

1. **源文档准备**
   - 确保文档格式正确
   - 标题层级清晰
   - 内容完整连贯

2. **分段处理**
   - 大文档（>100页）建议分批处理
   - 每批 20-30 页

3. **质量把控**
   - 先小规模测试
   - 检查改写质量
   - 调整参数
   - 再大规模应用

4. **人工审核**
   - 重点审核低质量片段
   - 修改事实不一致的部分
   - 保存修改后的版本

### 适用场景

✅ **适合**：
- 校史、厂史、地方志等大规模文本
- 风格迁移改写
- 批量文档处理
- 需要保持风格的改写

❌ **不适合**：
- 单篇短文（<1000字）
- 需要精确翻译的场景
- 需要完全创新的写作
